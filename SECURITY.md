# Security policy

## Reporting a vulnerability

Do not open a public issue for a suspected vulnerability. After the repository is published, enable
GitHub private vulnerability reporting under **Settings → Security → Code security and analysis** and
use that channel. Until then, contact the repository owner privately.

Include affected version, reproduction steps, likely impact, and any suggested mitigation. Do not
include real secrets or confidential documents in a report.

## Supported versions

Until the first stable release, only the latest commit on `main` receives security fixes.
